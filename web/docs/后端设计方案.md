## 一、Lombok 使用规范

| 注解 | 使用位置 | 作用 |
|------|----------|------|
| @Data | 全部 entity / dto / vo | 自动生成 getter/setter/toString/equals/hashCode |
| @Slf4j | 全部 service 实现类与 controller | 日志对象 log.info/error，替代手写 Logger |
| @RequiredArgsConstructor | service 实现类 | 配合 final 字段实现构造器注入（推荐替代 @Autowired） |
| @NoArgsConstructor / @AllArgsConstructor | entity（MyBatis 反射需要无参构造） | 按需补充 |

pom.xml 已含 lombok 依赖与 maven-compiler-plugin 注解处理器配置，无需改动。

## 二、前后端分离架构

项目采用前后端分离设计，目录规划如下：

```
企业实习/web/
├── web/          # 后端（本方案范围）：Spring Boot 工程，仅提供 JSON REST API，不做页面渲染
└── web-ui/       # 前端（后续单独设计）：Vue3 + Vite 工程，独立文件夹，与后端零耦合
```

后端职责边界：只负责接口、业务逻辑与数据持久化，所有接口返回 JSON；不引入模板引擎，不放任何静态页面。前端通过 HTTP + JSON 交互，登录态用 Authorization 请求头传递（不依赖 Cookie/Session）。

跨域配置：前端开发服务器（默认 http://localhost:5173）与后端 9090 端口不同源，需在 WebConfig 中注册 CORS 配置（允许该来源的 GET/POST/PUT/DELETE 与请求头），生产部署时可改由前端 Nginx 反向代理统一同源。

## 四、通用机制

1. 统一响应：所有接口返回 `Result<T>`，code=0 成功，非 0 失败（1 通用失败 / 401 未登录 / 403 无权限）。
2. 异常处理：GlobalExceptionHandler 捕获 BusinessException（返回其消息）、数据校验异常、兜底 Exception（不暴露堆栈）。
3. 认证：POST /api/login 校验工号+MD5 密码 → 签发 token（HMAC-SHA256，payload=empId+role+过期时间，24h）→ 前端存 localStorage，后续请求带 `Authorization: <token>` 头。
4. 鉴权：LoginCheckInterceptor 拦截 /api/**（放行 /api/login）；标记管理员接口用路径约定 `/api/admin/**` 统一校验 role=admin，或按接口注解。
5. 当前用户：拦截器解析 token 后写入 UserContext（ThreadLocal），afterCompletion 清理；approver_id 等直接取当前登录工号。
6. 分页：手写 LIMIT 分页（避免 PageHelper 与 Spring Boot 4 兼容风险），Mapper 接口参数带 offset/limit，配套 count 查询。
7. 事务：员工新增/修改（emp + emp_expr 批量）、审批通过联动更新 emp、删除部门校验，统一 @Transactional。

## 六、关键实现要点

1. 密码：MessageDigest MD5 32 位小写，与库内测试数据（123456）一致。
2. Token：自实现 HMAC-SHA256（base64(header).base64(payload).base64(hmac)），不引入第三方 JWT 依赖，降低 Spring Boot 4 兼容风险。
3. 员工分页查询：XML 动态 SQL（if 标签拼接条件 + LIMIT #{offset}, #{pageSize}）。
4. 删除员工：同事务删除 user 账户与 emp_expr，防止孤儿数据。
5. 审批幂等：仅 status=0 的单据可审批，重复审批返回业务异常。
6. MyBatis：map-underscore-to-camel-case 已开启；insert 返回自增主键（useGeneratedKeys）。
